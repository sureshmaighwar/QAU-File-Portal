1 Project Overview

Project Title

QAU File Sharing & Tracking System (QAU-FSTS)

Introduction

A centralized, secure web portal for Quaid-e-Azam University enabling file sharing with complete tracking — who uploaded, where shared, and who downloaded with exact timestamps. The system auto-detects user roles from credentials (email/registration number), enforcing strict access boundaries for Admins, Faculty, and Students.

Problem Statement

  • ● No centralized file sharing — files circulate via WhatsApp, email, USB
  • ● Zero visibility into who accessed sensitive academic documents
  • ● Students have unrestricted access (security risk)
  • ● No audit trail for compliance or accountability
  • ● Version control chaos across departments

Solution

A unified web portal providing: centralized file storage, auto-detected role-based access control, real-time download tracking, immutable activity logs, department-wise file organization, and a modern QAU-branded interface (Green, Gold, Blue) requiring zero training.

3 Auto Role Detection & Access Control

🔐 Auto Role Detection Logic

Users enter only email or registration number. The system detects the role automatically:

👑 Admin

Email starts with admin@, hod@, director@

👨‍🏫 Faculty

Email contains @qau.edu.pk with dr. or prof.

🎓 Student

Registration number: 2024-CS-156, fa24-xxx

ADMIN

Full System Control

  • ✅ Upload unlimited files
  • ✅ Share with anyone
  • ✅ Delete any file
  • ✅ View ALL analytics
  • ✅ Manage all users
  • ✅ View complete audit logs
  • ✅ System configuration
FACULTY

Department Level Access

  • ✅ Upload files (500MB limit)
  • ✅ Share with students/departments
  • ✅ Delete own files only
  • ✅ View department analytics
  • ✅ Track downloads on own files
  • ❌ Cannot manage users
  • ❌ Cannot access system settings
STUDENT

Limited Read-Only Access

  • ✅ View files shared with them
  • ✅ Download permitted files
  • ✅ View own download history
  • ✅ Receive notifications
  • ❌ Cannot upload files
  • ❌ Cannot share files
  • ❌ Cannot see analytics
  • ❌ Cannot access admin logs

⚠️ Critical Security Note on Student Access

Students are strictly limited to Read/Download operations. Allowing students to upload or share files introduces severe risks: malware injection, exam paper leaks, and unauthorized distribution. These limitations are enforced at the database and API middleware level, not just the UI, making bypass impossible.

7 Database Schema (Django Models)

👤 CustomUser Model

id UUID PRIMARY KEY
email VARCHAR UNIQUE
registration_no VARCHAR UNIQUE
full_name VARCHAR(100)
role ENUM('admin','faculty','student')
department FK → Department
password_hash VARCHAR(255)
is_active BOOLEAN

📁 File Model

id UUID PRIMARY KEY
name VARCHAR(255)
file FileField (AWS S3)
size_bytes BIGINT
uploaded_by FK → CustomUser
department FK → Department
is_public BOOLEAN
download_count INTEGER

📥 DownloadLog (Tracking)

id UUID PRIMARY KEY
file FK → File
user FK → CustomUser
downloaded_at TIMESTAMP
ip_address VARCHAR(45)
user_agent VARCHAR(500)
device_type ENUM

🔗 FileShare Model

id UUID PRIMARY KEY
file FK → File
shared_by FK → CustomUser
shared_with_user FK → CustomUser
shared_with_dept FK → Department
permission ENUM('view','download')
expires_at TIMESTAMP
